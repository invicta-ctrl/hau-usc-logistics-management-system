# Brand Assets Guide

The System Owner governs six public brand slots through protected production
routes and the dedicated production R2 binding.

1. Select the intended slot and upload only an approved type and size.
2. Review the server-derived byte count, content type, and SHA-256 identity.
3. Publish the new version; do not overwrite the prior object or history row.
4. Verify the public governed route on desktop and mobile.
5. Roll back by selecting a retained version through the protected workflow.

Administrator may inspect governed brand state but cannot perform owner-only
mutations. Object keys, bucket/provider identifiers, and private metadata must
not be shown in public responses or copied into Git.
