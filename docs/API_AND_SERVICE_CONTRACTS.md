# API and Service Contracts

## Contract boundary

The browser calls semantic methods on the launch service contract. In **CURRENT Apps Script mode**, `AppsScriptAdapter` maps those methods to global `api_*` callables. In **DEMO mode**, a mock adapter implements the user-visible workflow with fictional data. `HttpApiAdapter` maps the same method names to `POST /api/{method}`, but that server is **FUTURE** and currently unconfigured.

Every Apps Script callable returns a client-safe envelope:

```json
{
  "ok": true,
  "correlationId": "fictional-correlation-token",
  "resultField": "operation-specific value"
}
```

Failures return `ok: false`, a stable `code`, safe `message`, `correlationId`, `retryable`, and safe `details`. Raw stacks and configured resource values remain in controlled logs. The adapter converts failed envelopes, timeout, and platform failures into `AppError` instances.

For every mutation:

1. The browser reuses `clientRequestId` while a retryable attempt is unresolved.
2. The server resolves identity, checks the command-specific permission, validates all fields, and obtains a script lock where state can race.
3. The server rechecks current state, allocates canonical IDs, writes the business change, appends status/audit records, records the idempotent result, and advances the revision once.
4. The browser reloads authoritative bootstrap data. It never assumes that the command response is a full state snapshot.

## Request, reservation, and release callables

| Browser method / Apps Script callable   | Key input and result                                                                                                           | Permission                                                      | State and audit effect                                                                                                 | Principal failures / tests                                                                 |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |

| `reviewRequest` / `api_reviewRequest`   | `{requestId, decision, note, clientRequestId}`; returns routed line results                                                    | `Can_Review`                                                    | Under one lock, accepts/rejects and routes every line; creates reservations or procurement work; appends history/audit | Stale status, insufficient ATP, VERIFY, invalid decision; all-or-nothing acceptance tests  |

## Error taxonomy

| Class                       | Examples                                                                                       | Retry guidance                                                                        |
| --------------------------- | ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| Validation or policy        | `VALIDATION_ERROR`, `ITEM_NOT_SELECTED`, `UNSUPPORTED_FILE_TYPE`, `ITEM_REQUIRES_VERIFICATION` | Correct input or resolve policy; do not replay unchanged                              |
| Authorization               | `UNAUTHORIZED`, `FORBIDDEN`, `CATALOG_PERMISSION_REQUIRED`                                     | Stop; an administrator must review access                                             |
| Conflict or stale state     | `INSUFFICIENT_STOCK`, `RESERVATION_CONFLICT`, invalid transition/dependency                    | Reload authoritative state and start a new reviewed command                           |
| Configuration               | `SETUP_REQUIRED`, `CONFIGURATION_INVALID`, `DRIVE_FOLDER_INVALID`, `SCHEMA_MISSING`            | Stop writes and repair configuration in the correct environment                       |
| Contention/transient        | `LOCK_TIMEOUT`, browser timeout, platform failure                                              | Preserve the idempotency key and retry only when the client marks the error retryable |
| Recorded but refresh failed | Successful mutation followed by bootstrap failure                                              | Do not resubmit; perform read-only Refresh and reconcile by correlation ID            |

## Contract change checklist

When adding or changing a callable, update the launch contract, Apps Script adapter, mock implementation, future HTTP mapping, permission check, input validation, idempotency/lock behavior, audit/history shape, safe error mapping, this catalog, and tests in one bounded change. A browser-only method or an Apps Script-only method is an incomplete contract unless explicitly documented as operator-only.
