# HAU-USC Logistics Management System — Operational Product Roadmap to v1.0
## START HERE
### Product Mission
- Give the Department of Logistics one accountable workspace for requests, canvassing, procurement, food, materials, inventory, pantry, lending, releases, event readiness, reporting, and audit history.
- Make the simple path obvious to DOL staff while keeping technical controls available to maintainers.
- Keep Google Apps Script and Google Sheets as the current platform and cross-device operational record. Any database migration remains a future decision, not part of the current build.
### Scope and Boundaries
- Primary users — Department of Logistics
- Secondary users — authorized HAU-USC departments
- Internal Office Lending Hub remains DOL-controlled through v1.0
- General HAU student lending, public access, Microsoft/Entra authentication, and institution-wide deployment are post-v1.0 decisions
- Financial and borrower information is restricted to authorized users and audited

### Current implementation decision — July 11, 2026
- The capability audit is classified **FIX LATER**; the current work is a visual and workflow preview, not a production merge.
- Requesters do not enter a budget or estimated price. DOL reviews the need, canvasses supplier prices, and prepares any later DOF budget-approval request before procurement.
- The request center has two distinct paths: **Event Logistics** and **Office Restock**.
- **Inventory Management System** is the main catalog/availability view. **Event Deliverables**, **Restocking**, **Register Product**, and **Canvassing** are separate workflows linked by request, event, product, supplier, and ledger references.
- Event Deliverables requires the requesting department to check received lines and submit a receipt confirmation with name, role, time, and remarks.
- Reorder Level is not a user-facing requirement. Availability and review status are used instead.
- Current visual revision: `Index_Frontend_Visual_Preview_Revision_02_2026-07-11.html`; acceptance is still pending.
### July 4 Operating Rules
- DOL has Food, Inventory, and Materials committees; heads summarize factual committee information to the Director.
- Venue, materials, and food requests use different lead times measured in business weeks.
- Sunday and exam week are excluded from business-week calculations.
- All items entering or leaving the office are requested and accounted for; emergency paper-strike forms are the exception.
- Borrowing requires a completed request and School ID; event releases require authorized staff and handoff confirmation.
- Materials use DOL canvassing before purchase; the supplier list is maintained for council reference.
- RFB, PCV, AS, receipts/invoices, and cash disbursement records form the financial paper trail.
### Pilot Release — YDD 2026
- Use Siglinang: Youth Development Days 2026 as the first operational readiness pilot.
- Track venue/equipment, procurement/materials/food, awards, sponsors, assignments, deadlines, and completion evidence.
- Event dates — August 10 and August 12, 2026
- Pilot gate — every task has an owner, deadline, status, dependency, and evidence before the event.
### Roadmap Operating Guide
- Open a phase node for purpose, deliverables, owner, dependencies, evidence, and next action.
- Use GitHub issues for implementation tasks and roadmap nodes for outcome-level progress.
- Keep one active delivery phase; use BLOCKED when a decision or approval is missing.
- Mark a phase DONE only after its release gate passes and evidence is linked.
- Use the YDD pilot as the first real-world validation of request, task, inventory, and reporting workflows.
### Status Legend
- CURRENT — actively being implemented
- NEXT — prepared after the current gate
- PLANNED — approved direction but not active
- BLOCKED — waiting for approval, data, access, or dependency
- DONE — release gate passed with evidence

## CROSS-CUTTING STANDARDS
### Security and Privacy Standard
- Deny access by default; enforce permissions in backend and database policies.
- Never trust hidden buttons as security; test direct calls and out-of-scope records.
- Restrict borrower, financial, supplier, and audit data by role and scope.
- Audit privileged changes, stock changes, approvals, and access changes.
### Data Integrity Standard
- Inventory is an append-only ledger; balances are calculated, not edited as truth.
- Requests, approvals, fulfillment, loans, returns, and financial documents retain history.
- Use stable internal IDs and human-readable display IDs.
- Reconcile every import, migration, cutover, and report export.
### User Experience Standard
- Put plain-language labels first and technical detail behind accessible help controls.
- Make essential instructions visible outside tooltips.
- Use text plus color for status; support keyboard, touch, mobile, loading, error, success, and empty states.
- Explain consequences before destructive, approval, stock, or access-changing actions.
### Development and Change Standard
- One GitHub issue or vertical slice per Codex task.
- Inspect and plan before implementation; avoid one-shot rewrites.
- Every change includes tests, diff review, limitations, rollback notes, and updated status.
- Stop when the approved acceptance criteria pass.
## MANAGEMENT AND MONITORING
### Simplified Admin Portal
- Manage users, roles, department scopes, departments, reference values, workflow rules, alerts, audit history, and reports.
- Use previews, confirmations, consequences, and recovery guidance.
- Never expose a raw database editor to nontechnical administrators.
### Technical Maintainer Toolkit
- GitHub — source, issues, pull requests, milestones, release history
- Supabase — database, authentication, policies, migrations, logs, backups
- Hosting — previews, staging, production, environment settings, rollback
- CI — linting, types, tests, builds, security, and migration checks
- Runbooks — deployment, incident response, restoration, export recovery, and handover
### Google Sheets Reporting
- Read-only reports show source system, last refreshed time, row counts, and export status.
- Reports cover inventory, low stock, requests, loans, overdue items, movement, department usage, audits, procurement, and event readiness.
