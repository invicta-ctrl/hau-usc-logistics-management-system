# Requester Guide

## What this portal does

The Request Center lets an approved requester submit event-logistics or catalog-restock needs for DOL review. Submission does not reserve, deduct, procure, or guarantee stock. DOL staff review each line against current inventory, policy, timing, and procurement needs.

The local preview is DEMO and uses fictional data. A real request is recorded only when the authorized institutional portal confirms success with a request reference.

## Submit a request

1. Open the official request-only portal address supplied by HAU/USC. Do not use an address copied from an untrusted message.
2. Choose the request type and, for event logistics, the approved event/date context.
3. Enter the minimum requester/department/purpose information required by institutional policy.
4. Add each item line:
   - choose an exact catalog suggestion when you mean an existing stock item;
   - otherwise enter a clear specification, controlled category, quantity, and unit for DOL review;
   - do not enter personal data, passwords, tax numbers, or confidential notes in an item description.
5. Review duplicate lines, quantities, units, dates, and purpose.
6. Submit once and wait for the result. Save the request reference through the approved channel.

The portal intentionally does not reveal exact stock, reservations, supplier details, borrower history, internal users, audit logs, or Drive evidence. A label such as “pending DOL review” means the server will decide the route later.

## Exact catalog selection

Typing text is not enough to identify inventory. Select a suggestion so the hidden canonical item ID is attached. Free text can describe a new need, but it will never deduct an existing item automatically. `VERIFY`, inactive, archived, or audience-restricted items cannot be promised through the requester screen.

## Dates and quantities

Use the actual needed date and enough specification for DOL to distinguish similar items. Quantities must be positive and units must match the intended item. Lead-time, exam-week, event, and procurement rules may cause review or rejection even when a line looks available.

## After submission

DOL may accept, partially route, send for canvass/procurement, ask for clarification, reject, or cancel a line according to policy. Reservations occur only during authorized review. Physical release still requires recipient verification and confirmation. Keep the request reference when following up; do not send a screenshot containing personal/internal data to a public channel.

## Errors and retries

| Message type                                   | What to do                                                                            |
| ---------------------------------------------- | ------------------------------------------------------------------------------------- |
| Required/invalid field                         | Correct the highlighted value and submit again                                        |
| Item not selected                              | Choose a catalog suggestion or intentionally use a new-item specification             |
| Unauthorized/internal page denied              | Return to the official request-only portal; ask DOL if access is expected             |
| Busy or temporary failure marked retryable     | Keep the form open and retry once; the portal reuses the safe request key             |
| Submission confirmed but screen cannot refresh | Do not submit again; use Refresh and provide the correlation/request reference to DOL |
| Offline                                        | Reconnect before submitting; no real request is queued offline                        |

If you are unsure whether a request was recorded, contact DOL with time and the safe reference/correlation ID—never your password or a resource URL.

## Privacy and safe use

- Use only the minimum approved personal information.
- Do not upload evidence unless the workflow explicitly requests an approved file type and you are authorized.
- Never place passwords, payment credentials, health data, unrelated student records, or supplier tax details in purpose/notes.
- Sign out of shared devices and close the browser. The current operational app does not promise offline access.
- Report a suspicious portal address, unexpected internal data, or misdirected record immediately through the institutional incident channel.
