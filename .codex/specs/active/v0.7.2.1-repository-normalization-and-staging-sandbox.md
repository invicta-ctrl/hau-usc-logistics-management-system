## Generated-artifact policy

Tracked `dist/index.html` and `dist/_headers` remain the canonical preview artifact because shareable parity currently depends on them.

- Preview builds may regenerate canonical tracked output.
- `verify:dist` must prove preview-mode identity and byte equality with a fresh isolated preview build.
- Staging, production, Cloudflare dry-run, deployment, and local Worker acceptance must build into isolated output directories.
- Non-preview builds must leave all tracked preview/shareable/Apps Script artifacts byte-identical.
- Deployment consumes and verifies an isolated exact-SHA artifact.
- Generated files are never hand-edited.

## CI policy

The canonical repository gate runs governance/handoff checks, lint, canonical preview build, unit tests, Apps Script validation, fresh generated parity, and an isolated Cloudflare dry run exactly once. Keep distinct browser, local Worker/D1, deployed staging, migration, release-candidate, recovery, and CodeQL gates because they prove different boundaries. Evidence is reused only for the exact SHA/artifact/configuration until an invalidator changes.

## Permanent staging sandbox

Repository commands:

- `staging:sandbox:status`
- `staging:seed-sandbox`
- `staging:reset-sandbox`

All commands require an absolute private staging configuration outside Git. Reset also requires `SANDBOX_RESET_ALLOWED=true`.

### Mandatory guard order

1. Assert `ENVIRONMENT == STAGING` and the exact staging Worker/D1/R2 identity.
2. Reject every production binding and crossover.
3. Verify exact candidate SHA; feature-candidate staging SHA need not equal production SHA.
4. Require an exact normalized owner/test email allowlist for staging.
5. For reset, prove all active operational rows are recognized synthetic sandbox data.
6. Capture a fresh private backup/recovery point.
7. Restore in isolation and require `PRAGMA integrity_check = ok` and zero foreign-key violations.
8. Archive, close, disable, reverse, or reinitialize only manifest-approved synthetic state; never run generic table deletion.
9. Preserve all immutable history, audit, ledger, evidence, migration, schema, and recovery records.
10. Reseed the canonical versioned dataset and run authorization, ledger, idempotency, account, workflow, recovery, login, and denial checks.
11. Report only sanitized version, candidate SHA, schema/migration, seed version, aggregate counts, and boolean safety status.

### Seed contract

The deterministic seed covers System Owner, Administrator, Director/reviewer, DOL staff, committee heads/members, requester, lending-only, disabled, and denied actors; 30-50 representative inventory items; low/out-of-stock, consumable/reusable, restock/receiving, event, Request, review/routing, Deliverable, Release, Lending/return, and permission-denial states. Identities use visibly synthetic values such as `example.invalid`; generated credentials remain in an owner-private file and never in Git or logs.

### Visual identity and email containment

Only staging renders a persistent `STAGING TEST ENV` banner with version, candidate SHA, schema, and optional sanitized branch label. Production renders neither the banner nor staging metadata.

Staging readiness fails closed when the exact-recipient allowlist is absent, empty, invalid, or ambiguous. No wildcard or domain-only rule is accepted. Recipient validation occurs before any network/provider call. Rejected recipients produce only sanitized evidence and zero outbound calls.
