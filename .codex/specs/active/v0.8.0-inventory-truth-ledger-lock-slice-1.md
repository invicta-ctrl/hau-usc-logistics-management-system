## Test strategy and defect rule

Inventory existing tests first and reuse exact-boundary evidence. Add only missing,
deterministic focused tests, preferring domain/service/Worker-D1 boundaries. Cover,
where implemented, opening/inbound/outbound derivation; reservation creation,
release/cancellation, and over-reservation; request submission non-deduction;
availability-only reservation effects; cumulative receiving; release stock recheck;
single lending custody/stock effects; retry idempotency; transfer pairing; adjustment
audit; denied mutation; and requester/public privacy.

Do not weaken expected results or commit a knowingly red canonical suite. A discovered
product defect receives an ID `V080-S1-INV-NN`, severity, deterministic reproduction,
authoritative boundary, consequence, proposed Slice 2 regression test, smallest likely
repair boundary, and migration impact. P0/P1, authorization/privacy, immutable-history,
recovery, corruption, or data-integrity defects are immediate stop conditions.
