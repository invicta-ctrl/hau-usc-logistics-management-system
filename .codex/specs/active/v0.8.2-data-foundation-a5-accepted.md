# v0.8.2 Data Foundation — A5 Accepted Bounded Specification

STATUS: ACCEPTED_OWNER_A5

## Authority

- Earl's A5 authorization and latest explicit continuation instruction.
- `.codex/specs/active/v0.8.1-v0.8.5-v1r7a3-standalone-master-program.md`.
- Owner-provided private V082-V085 preflight companion, revalidated against the
  completed v0.8.1 S17 baseline.

## Objective

Strengthen the existing data foundation without changing its authority model:
D1 remains structured operational truth, R2 remains authoritative private
evidence, Sheets remains a read-only secondary source/projection, and Drive
remains verified backup/recovery only.

## Included lanes

### DATA-A — source contract/read path

- Reuse the existing read-only roster-source contract and its normalization,
  fingerprint, and validation seams.
- Preserve the import cutover guard; Apps Script is not a D1 fallback after
  cutover.
- Keep protected source fields out of repository artifacts, logs, and ordinary
  status DTOs.

### DATA-B — evidence durability

- Reuse the existing D1 evidence outbox, R2 verification, Drive backup/recovery,
  idempotency, audit, retry, and System Owner-only controls.
- Add focused fault-injection or regression coverage only where a confirmed
  contract gap exists.

### DATA-C — reconciliation

- Use the schema-30 read-only reconciliation seam against an authorized
  synthetic or private export fixture.
- Classify discrepancies as reconciled, quarantine, or blocking; never
  auto-repair ledger, reservation, roster, or source rows.

## Explicit exclusions

- DATA-D import writes, Sheets writeback, dual-write, source backfill, and
  automatic repair.
- New migration, durable cursor/ledger/history, or schema change.
- Provider, Production, Google, D1, R2, email, secret, or deployment mutation.
- Raw names, student identifiers, emails, review notes, provider identifiers,
  credentials, secrets, or private resource values in Git, logs, artifacts, or
  status DTOs.

## Invariants

- Existing guarded D1 batches, idempotency, revisions, append-only audit, and
  evidence-outbox seams remain authoritative.
- Reconciliation is read-only and fail-closed on blocking evidence.
- Sheets access is read-only and least-privilege; Drive cannot become
  operational truth.
- No migration is permitted in this first wave. A later durable cursor, sync
  ledger, quarantine record, or reconciliation-history need requires a separate
  accepted amendment.

## Acceptance evidence

- Focused unit and D1 tests for the touched contract paths.
- Redacted reconciliation disposition with schema, migration, checks, and
  counts only.
- Privacy scan proving no protected source/provider material entered the
  candidate.
- Governance, handoff, diff, and scope checks before any integration handoff.

## Stop conditions

- Any required source contract, privacy, schema, provider, or authorization
  invariant is absent or conflicts.
- Any need for import write, migration, external mutation, or raw protected data
  beyond the exclusions above.
