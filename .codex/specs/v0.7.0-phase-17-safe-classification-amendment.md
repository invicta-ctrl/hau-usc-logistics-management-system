# HAU-USC Logistics v0.7.0 Phase 17 Safe Classification Amendment

This focused owner-approved amendment permits the authoritative inventory to be
imported before physical classification is complete. It supplements Phase 17 of
`.codex/specs/v0.7.0-production-master.md`; all existing security, privacy,
ledger, audit, backup, staging-acceptance, production-authorization, and
truthful-evidence gates remain mandatory.

## Safe import state

An item without an approved physical classification is `UNVERIFIED` and
`NEEDS_CLASSIFICATION`. It is non-lendable, has no lending audience, has no
assumed condition or maintenance clearance, and receives no asset instances.
Name, category, quantity, stock area, and unit never imply reusable/consumable
kind, lendability, audience, condition, maintenance, or instance count.

Unclassified items remain visible only to authorized Inventory, Administrator,
Director, and System Owner users. Public and staff lending catalog, reservation,
Ready to Claim, and handoff paths must reject them even when ledger stock is
positive.

## Protected website workflow

The application must provide an authorized Needs Classification queue with
search, status filter, progress totals, pagination, individual review, and an
explicitly confirmed non-lendable-only bulk path for genuinely similar items.
The workflow records inventory kind, lending eligibility and audience, stock
area, storage location, handling, unit, reorder threshold, reusable condition,
maintenance review, traceable asset intent and records, notes, review status,
optional evidence reference, actor, timestamp, revision, and append-only
history.

Lending can be enabled only through explicit confirmation. Reusable items also
require a physically reviewed safe condition and maintenance clearance. Asset
instances may be created only from an explicitly entered count and matching
physical asset tags after the user confirms individual tracking; opening
quantity is never used as instance count.

## Physical counts

Opening quantities remain immutable `OPENING_BALANCE` ledger movements. Later
physical counts use the existing authorized append-only cycle-count adjustment
operation, recording the prior computed balance, observed count, delta, reason,
actor, timestamp, audit reference, and idempotency key. No catalog update may
overwrite a balance.

## Phase 17 acceptance

Phase 17 may retain pending real-world classifications only when all 397 source
rows import and replay idempotently, opening ledgers reconcile exactly, no
unexplained negative or mock stock remains, every pending row is visibly marked
and fail closed, the protected workflow and audit history operate on staging,
one controlled staging classification proves later explicit lending enablement,
the fixture is reconciled, and exact-head repository and CI gates pass.
