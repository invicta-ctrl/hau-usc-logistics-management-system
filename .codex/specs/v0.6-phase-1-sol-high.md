## GATE 3 — Authentication and Onboarding Foundation

Implement and verify:

### Login
- Access ID;
- password;
- no role selector;
- no committee selector.

### Starter account
Server-managed:
- Access ID;
- temporary password;
- predetermined role;
- predetermined committee scope;
- account status;
- onboarding incomplete / must-change-password state.

### First login activation
Require:
- full name;
- mobile number;
- email;
- new password;
- confirm password.

On success:
1. validate server-side;
2. link profile to existing account;
3. preserve server-managed role/scope;
4. store password using approved secure hashing/KDF;
5. invalidate temporary password;
6. mark onboarding complete;
7. record audit/history;
8. establish/refresh session;
9. resolve capabilities;
10. route to the correct experience.

The user must never self-select or change their own role/committee.

### Security requirements
Use an implementation appropriate to the actual runtime and repository architecture.

Require:
- no plaintext/reversible password storage;
- per-account salt where applicable;
- configurable work factor;
- timing-safe verification;
- secure session handling;
- HttpOnly cookies where applicable;
- Secure cookie attributes in production;
- CSRF protection where applicable;
- login throttling/rate limiting;
- temporary-password expiration;
- session invalidation after reset/revocation;
- server-side authorization on protected actions;
- audit trail.

### Negative tests
At minimum:
- wrong password;
- disabled account;
- revoked account;
- expired/replayed temporary password;
- replayed activation;
- invalid onboarding;
- user attempts self-escalation;
- unauthorized protected action;
- direct API call without required capability.
