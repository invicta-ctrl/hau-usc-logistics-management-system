## GATE 7 — Cloudflare Frontend/API Migration

Move toward:

`Cloudflare Workers + Static Assets`
→ frontend

`Workers API`
→ auth / authorization / domain services

Preserve rollback.

Do not migrate every layer simultaneously.

### Requirements
- explicit HTTP/service boundary;
- protected server routes enforce capabilities;
- session/auth model compatible with deployment architecture;
- static assets structured for Cloudflare;
- action-driven refresh replaces continuous 15-second polling as the normal long-term strategy;
- module/page open loads current data;
- successful mutation refreshes affected data;
- tab activation may perform bounded freshness check;
- manual refresh remains available;
- sensitive transactions revalidate authoritative server state immediately before commit.

Do not deploy to production automatically.

## GATE 8 — D1 + GOOGLE SIDECARS

### D1
Introduce through explicit migrations.

Operational target:
- D1 = structured operational source of truth.

Require before consequential migration:
- exact target;
- backup;
- dry run;
- reconciliation;
- rollback;
- integrity checks;
- migration tests;
- ledger/history preservation.

### Google Drive
Keep as evidence/file sidecar unless later accepted architecture changes it.

Require controlled folder mappings and standardized names for:
- release photos;
- restock receipts;
- invoices;
- quotations;
- canvass evidence;
- return-condition photos;
- deliverable receipts;
- supporting documents.

Store metadata links to the correct domain entities.

Never silently fall back to the script owner's My Drive root.

### Google Sheets
Use for:
- reporting;
- export;
- monitoring;
- human-readable management views.

After D1 migration, manual Sheet edits must not become the normal transactional mutation path.

Keep a clear audit boundary between database truth and reporting projection.

### Apps Script
Retain only as a narrow Google-integration bridge where useful.

Do not retain it as permanent primary UI host solely for backward compatibility.

## TRANSACTIONAL HARDENING

Review and verify the highest-risk workflows.

### Release Desk
Must remain:
- atomic;
- idempotent;
- audited;
- validated against current stock/reservation state immediately before commit.

### Inventory
Preserve:
- append-only ledger;
- onHand;
- reserved;
- availableToPromise;
- reversal/adjustment instead of mutating posted ledger entries.

### Receiving
- cumulative;
- never overwrite previously received quantity;
- prevent over-receiving where disallowed.

### Lending
- duplicate handoff blocked;
- duplicate return blocked;
- cross-device persistence;
- eligibility enforced server-side.

### Reservations / acceptance
Where concurrent state may race:
- use appropriate transactional/locking mechanism for the final runtime;
- revalidate authoritative state before mutation.

Add or strengthen regression tests when practical.
