# HAU-USC Logistics v0.7.1 Production Recovery

This specification is the durable, owner-accepted contract for the v0.7.1
production-recovery release. It extends the accepted v0.7.0 production
baseline and its amendments. It does not rewrite, retag, or weaken v0.7.0.

The owner accepted the attached master execution packet and routing-attestation
amendment by directing Codex to execute them. The amendment changes only the
routing-attestation gate: accepted platform routing plus behavioral isolation
is sufficient when exact runtime identities are not agent-visible. All product,
security, privacy, provider, rollback, review, and owner-approval gates remain.

## Objective

Recover the confirmed production usability and client-contract defects, make
the Staff Directory, Access Management, workspace, Canvass, and Inventory
flows dependable for near-term operations, and prepare a reviewable v0.7.1
candidate with preview, rollback, and monitoring evidence. Production and
destructive external actions remain separately owner-gated.

## Confirmed starting defects and facts

- Live production truthfully reports `PRODUCTION`, v0.7.0, the immutable
  v0.7.0 release candidate, schema 29, readiness true, and protected bindings
  available. Live staging reports `STAGING` and the same immutable source.
- The Staff Directory and Access Management Worker routes exist, but the
  browser adapter surface is incomplete. The legacy runtime adapter omits
  roster and access-policy methods used by the UI, and the HTTP adapter omits
  the access-policy methods. Runtime-extension fallbacks then conceal the
  missing contract. This is the confirmed cause of the raw method failures.
- The production Request Center lacks the complete staff-sign-in/portal-choice
  navigation contract. The Lending Center presents a borrower selector that
  requires the bounded visual/accessibility correction.
- The canonical staff domain is active. The requested public subdomains are
  not yet active, and source currently routes by pathname rather than hostname.
- Repository CI verifies source and browser smoke, but no repository workflow
  currently implements GitHub-to-Cloudflare previews or owner-gated deploys.
- No current fact indicates production is bound to staging D1 or R2 resources.

## User flows and behavior contracts

### Service contract and safe failure

The browser service contract is explicit and testable. Adapters expose every
method consumed by a screen, mutations retain idempotency tracking and CSRF,
and each method reaches its documented Worker route. Missing optional provider
configuration may produce a truthful `Not configured` state; missing code must
not be presented as provider unavailability. A screen failure uses:

> This section is temporarily unavailable. No records were changed. Reference: ABC123

### Login and hosts

Staff sign-in lands on the canonical authorized workspace. Activation and
password reset enforce the accepted eight-character minimum and revoke stale
sessions where required. Logout invalidates the active session. Unauthorized
deep links fail closed. Session cookies remain Secure, HttpOnly, SameSite=Lax,
Path=/, without a shared Domain attribute unless a later accepted security
amendment proves a need.

### Canonical workspaces

Workspace selection is navigation, not an in-place label change. URL, title,
sidebar, dashboard, queues, metrics, available actions, role context, browser
history, and refresh state follow the selected canonical route. Operational
Scope appears only when it changes authorized records or actions and never
changes capability.

### Dirty forms

Dirty state compares current normalized values with the loaded/default
snapshot. Untouched close is immediate; changed close opens `Discard unsaved
changes?` with `Continue editing` as the safe primary action and `Discard
changes` as destructive. Focus is trapped, Escape returns to editing, and
successful save resets the snapshot.

### External systems

Cloudflare, domains, Google Drive, and Google Sheets begin read-only. Provider
writes require exact target identity, backup/rollback where applicable,
redacted evidence, and the specific owner gate. Google cleanup is
inventory-first and never infers purpose from a name alone.

## Exclusions

- Complete v0.8.0 visual rearchitecture, dashboard redesign, Request Center
  rebuild, Lending Center redesign, or an unrelated theme.
- `hallmark redesign`; Hallmark may be used only for audit and bounded polish.
- Finished QR ticket workflow unless separately accepted.
- Broad database redesign or any migration not separately specified and
  accepted.
- Automatic production deployment on merge.
- Permanent deletion of Google resources, backups, immutable history, or
  unknown local/repository work.
- Rewriting or retagging v0.7.0.

## Implementation slices and review gates

1. Specification, routing/TOML evidence, and read-only production truth.
2. Client/runtime contract parity and safe errors.
3. Login/session and public-portal navigation.
4. Staff Directory and Access Management.
5. Canonical workspace routing, integer quantities, borrower selector, and
   dirty-form protection.
6. Canvass and Inventory readiness.
7. Wording, naming, and Hallmark-bounded polish.
8. Preview/pipeline/domain preparation, integrated verification, rollback,
   monitoring, and release documentation.

Parent Sol is the sole integration-branch writer. Routine and complex work may
be delegated through isolated read-only or non-overlapping task packets. Every
material slice receives a new read-only review context with exact base/head
SHAs. Reviewer repairs are never applied by the reviewer.

## Rollback and stop conditions

Prefer immutable Worker-version rollback without database reconciliation.
Stop on wrong production binding, staging identity in production, P0 data risk,
unaccepted migration need, privacy/authorization uncertainty, unknown dirty
work, ambiguous external target, cleanup involving an active source/backup, or
missing owner credentials/approval. Roll back for identity drift, contract
errors, broken login/session revocation, directory/access failure,
domain-critical access failure, or integrity-check failure.
