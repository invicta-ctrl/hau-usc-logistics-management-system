## GATE 5 — Request Center and Lending Hub

### Request Center
Preserve the strongest current Request Center patterns.

Support:
- Event Logistics Request;
- Catalog / Office Restock Request.

Event Step 4 must expose together:
- Food;
- Materials;
- Venue & Equipment.

The requester may complete one, two, or all three.

Untouched categories create no child data.

Do not require an earlier checkbox step just to reveal them.

Implement:
- Original Request ID dropdown filtered by event series/sub-event;
- combined date-range interaction;
- predictive item search by item name, product ID, alias, category, stock area;
- line routing presentation:
  - Issue from Stock
  - For Canvassing
  - Split Fulfillment

Request submission must never deduct physical stock.

Do not invent final permanent Venue fields. If the authoritative venue form is unavailable, leave only that dependent mapping unresolved and continue unrelated work.

### Lending Hub
Preserve form + open-ticket split.

Student ID:
- digits only;
- no letters/symbols;
- max 8 digits unless authoritative rule changes.

Borrower eligibility:
- USC Officer/Staff must validate against approved active source, not domain alone;
- Angelite/Student uses approved identity rule.

Lifecycle:
- FOR_REVIEW
- READY_TO_CLAIM
- ON_LOAN
- OVERDUE
- RETURNED

Consumables:
- FOR_REVIEW
- READY_TO_CLAIM
- ISSUE
- COMPLETED

Respect the Phase 1 authorization/security contracts.

Prevent duplicate handoff/return through the existing server/domain boundaries; do not weaken them for UI convenience.

## MODEL ESCALATION RULE

Continue with Terra by default.

Escalate the affected task back to Sol only when one of these occurs:

1. Authentication/session architecture must materially change.
2. Authorization/capability semantics are ambiguous.
3. Ledger or inventory invariants conflict.
4. Atomic/idempotent transaction behavior requires redesign.
5. A security boundary is unclear.
6. Migration/database architecture is implicated.
7. Two focused repair attempts fail and the root cause is architectural rather than local.
8. A repository/spec conflict cannot be safely resolved.

Do NOT escalate merely because:
- CSS is difficult;
- a component needs refactoring;
- a normal test fails once;
- responsive behavior needs iteration;
- a routine feature needs several files.
